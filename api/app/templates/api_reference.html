01 / Connect

Your first authenticated request

  1. Read GET /auth/providers and choose an enabled provider.
  2. Create a session with POST /auth/sessions. Supply username, password and provider.
  3. Call GET /auth/whoami to verify your identity and access.
cURL / bearer session
curl --fail-with-body \
  "https://YOUR_HOST{{ prefix }}/api/v1/auth/whoami" \
  -H "Authorization: Bearer $COYOTE3_SESSION_TOKEN"

Use your installation's public host. The token is the opaque session token from login, not a JWT or password.

02 / Authorize

Choose the right credentials

Browser session
Sign in to Coyote3 in this browser. The explorer sends your cookie and retrieves X-CSRF-Token for changes.
Bearer token
Use Authorize for an opaque session token. Bearer requests do not need a CSRF header. Credentials are not persisted by this explorer.
Pipeline ingestion
X-Coyote-Ingest-Token applies to the synchronous sample-bundle upload endpoint. Async ingestion and task polling require a user session.

03 / Handle responses

Resolve errors deliberately

StatusNext step
401Sign in again or replace expired session credentials.
403Check permissions, sample scope and cookie CSRF protection.
409Check the operation's conflict details, current revision and editing lease.
422Correct the fields identified by validation details.
5xxRecord X-Request-ID for support. Verify a write's outcome before retrying.

Error responses carry status, error and details. Keep credentials and patient data out of shared diagnostic examples.
