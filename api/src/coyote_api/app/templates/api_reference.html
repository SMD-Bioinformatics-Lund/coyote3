01 / Connect

Your first authenticated request

  1. Read GET /auth/providers for the enabled sign-in providers.
  2. Send username, password and provider to POST /auth/sessions.
  3. Use GET /auth/whoami to verify your identity and access.
curl --fail-with-body \
  "https://YOUR_HOST{{ prefix }}/api/v1/auth/whoami" \
  -H "Authorization: Bearer $COYOTE4_SESSION_TOKEN"

Use your installation's host. The opaque session token comes from the sign-in response's Set-Cookie header; it is not your password.

Authentication guide

02 / Authorize

Choose the right credentials

Browser session

Sign in to Coyote4 on this host. The explorer sends your session cookie and retrieves X-CSRF-Token for changes.

Bearer token

Send a session token as Authorization: Bearer <token>. In the explorer, paste the raw token into Authorize → BearerAuth. Bearer requests do not need CSRF. Credentials stay in this page only.

03 / Handle responses

Resolve errors before retrying

StatusNext step
401Sign in again or replace expired credentials.
403Check permissions, sample scope and browser-session CSRF protection.
409Read the conflict details. Refresh the current revision or editing lease before retrying.
422Correct the fields identified in the validation response.
5xxRecord X-Request-ID for support. Verify the outcome before retrying a write.

Error responses include status, error and details. Keep credentials and patient information out of shared examples.
