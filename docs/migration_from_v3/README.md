# Upgrade from Coyote v3

The v3 migration uses an offline BSON snapshot of `coyote3` and builds separate
annotation, blacklist, and per-sample bundles. It excludes users,
authentication records, external knowledgebases, and source backup collections.

Follow [Legacy clinical data migration](migration-guide.md) for the complete
procedure, source mappings, review-file format, TSV backfills, target application,
and acceptance checks. The
[v3 script package](https://github.com/SMD-Bioinformatics-Lund/coyote3/blob/api/scripts/upgrade_from_v3/README.md)
lists each command and the separate schema-maintenance tools.

## Source mappings

| Source | Destination |
| --- | --- |
| `samples` | `samples`, extracted `sample_comments`, and saved `reports` |
| `variants` | `variants`, extracted `finding_comments`, and `anno_vep` evidence |
| `cnvs` | `cnvs` and extracted finding comments |
| `transloc` | `translocations` and extracted finding comments |
| `biomarkers` | `biomarkers` with typed measurement payloads |
| `panel_cov`, measurement-shaped `group_coverage` | Sample-specific `d4_coverage`; ambiguous records require reviewed selection |
| Exclusion-shaped `group_coverage` | `d4_coverage_blacklist`; measurements never become exclusions |
| `reported_variants` | Preserved report-time finding snapshots |
| `annotation`, `blacklist` | Shared clinical annotations and blacklist entries |

ASP, ASPC, ISGL, assay groups, and subpanels must already exist in the destination's
current format. They are preflight dependencies, not legacy migration sources.

## Required review

Legacy assay groups do not automatically identify a current physical ASP.
Each sample needs an explicit ASP and an installed ASPC with matching environment,
subpanel, and omics layer. Historical filters require reviewed intent-specific
mapping. Old sequencing-technology labels require explicit platform/read-mode
mapping. Missing VEP versions block transcript-vault construction.

Case/control run names and read counts are preserved when recorded. Missing values
can be supplied using `scripts/upgrade_from_v3/backfill_sample_metadata.py` and a
reviewed TSV file. The converter does not assign the migration operator as the
historical ingest actor.

Clinical-rule and reporting-policy maintenance is separate from record conversion.
Use [Clinical-rule data maintenance](../operations/migrations/clinical-rule-migrations.md) only for the
documented target schema transition. Published report wording and historical report
content are not regenerated by this migration.

## Source schema assessment

Read [Full source schema inventory](schema-inventory.md) before conversion. Every
record and nested array element in the migration scope must be inventoried; one
example document or a small sample cannot establish a collection's schema.
