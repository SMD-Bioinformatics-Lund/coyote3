# RNA Clinical Review

Use the RNA sample workspace to review the analyses enabled by the sample's
recorded ASPC revision. Coyote3 shows only the analysis areas that apply to the sample and for which
the required data is available. An RNA sample therefore does not display DNA
SNV, CNV, translocation, or coverage tabs.

## Open an RNA sample

1. Open **Samples**.
2. Select an RNA sample.
3. Review the sample and analysis status on **Overview**.
4. Review **Fusions** under Findings in Classic, or open the **Fusions** tab in Modern.
5. Open **Reports** to review or create the RNA report when reporting is
   enabled.

The available analysis areas are derived from the recorded ASPC revision's analysis types, ingested
resources, application module controls, and the user's permissions.

Classic places Fusions and Expression & Classification together on the
Findings page when both are enabled. Modern presents them separately in tabs. The
same account preference controls DNA and RNA workspaces.

> **Info: Analysis availability**
>
>
> A missing analysis area normally means that the analysis is not enabled for that
> sample; it does not indicate an empty result set.
>

## Fusion Table

The fusion table is loaded from the sample fusion endpoint. Searching,
pagination, and sorting are applied by the API, so they operate on the complete
result set rather than only the rows visible on the current page.

| Column | Information shown |
| --- | --- |
| Select | Selects rows for an allowed bulk action. |
| Info | Curation and knowledgebase markers such as false positive, irrelevant, or COSMIC Cancer Gene Census (`CGC`). Hover a marker to read its meaning and matched gene context. |
| Gene 1 and Gene 2 | The two partners stored on the normalized fusion finding. |
| Effect | The predicted fusion effect, such as in-frame, when supplied by the source data. |
| SP | Spanning-pair evidence supporting the selected fusion call. |
| Unique SR | Unique split-read or spanning-read evidence, depending on the caller payload. |
| Fusion points | The available breakpoint coordinates for both partners. |
| Tier | The current matched clinical tier, a contextual tier requiring confirmation, or an evidence/selection status. A dash means no eligible tier match was found. |
| Description | Caller or annotation description associated with the selected fusion call. |
| Callers | The tools that reported the fusion. |
| Unlabeled detail column | Opens the fusion detail page. |

> **Info**
>
> Evidence counts are displayed as supplied by the pipeline. Their clinical
> interpretation depends on the assay, caller, and validated laboratory
> thresholds.
>

### Fusion tier matching

The table and detail page match the explicitly selected call's breakpoints and gene
context against annotations in the sample's clinical scope. The parent sample ID
preserves recorded historical links; caller names do not determine tiers.

| State | Display and action |
| --- | --- |
| Selected call with both breakpoints | Review the matched tier or classify the finding in the current scope. |
| Calls exist, none selected | **Select a fusion call**. Review the caller alternatives and use **Pick** to select one. The first caller is not used implicitly. |
| No calls, or selected call lacks a breakpoint | **Missing fusion evidence**. Review the source evidence; detail-page tier controls are unavailable until a selected call supplies both breakpoints. |

Inactive annotations do not automatically tier a new sample. Explicit sample/report
links can preserve a historical tier. See
[matching, deactivation and history](clinical-review-workflow.md#how-a-tier-is-matched).
COSMIC **CGC Tier** badges describe gene-level knowledgebase evidence and are separate
from this clinical classification.

## Search, Sort, and Export

- Enter a term in the table search field to search the server-side fusion data.
- Select one or more sortable headers to build a multi-column sort.
- Change the page size to control how many rows are displayed.
- Use **Export to CSV** to export the filtered fusion context generated by the
  API.

The table state is retained in the URL. Opening a fusion and returning to the
sample therefore preserves the active tab, search, page, and sort order.

## Curation Actions

Users with the required permission can mark or unmark selected fusions as
false positive or irrelevant. Coyote3 asks for confirmation before a mutation
is applied. Curated rows remain visible but use the standard subdued finding
style so that excluded findings are distinguishable from active findings.

## Reporting

The **Reports** tab is available only when reporting is enabled for the sample.
Report generation uses the filtered clinical context and the RNA report
sections permitted by the recorded ASPC revision. Review the rendered preview before
saving a report artifact.

For the configuration rules that determine visible analyses and report
sections, see
[Configuration identity and audit](../architecture/configuration-identity-and-audit.md)
and
[Reporting workflow](../reference/report-snapshots.md).
