# RNA Clinical Review

Use the RNA sample workspace to review the analyses enabled by the sample's
active ASPC. Coyote3 shows only the tabs that apply to the sample and for which
the required data is available. An RNA sample therefore does not display DNA
SNV, CNV, translocation, or coverage tabs unless a future assay contract
explicitly supports them.

## Open an RNA Sample

1. Open **Samples**.
2. Select an RNA sample.
3. Review the sample and analysis status on **Overview**.
4. Open **Fusions** when fusion analysis is enabled.
5. Open **Reports** to review or create the RNA report when reporting is
   enabled.

The available tabs are derived from the active ASPC analysis types, ingested
resources, application module controls, and the user's permissions. A missing
tab normally means that the analysis is not enabled for that sample; it does
not indicate an empty result set.

## Fusion Table

The fusion table is loaded from the sample fusion endpoint. Searching,
pagination, and sorting are applied by the API, so they operate on the complete
result set rather than only the rows visible on the current page.

| Column | Information shown |
| --- | --- |
| Selection | Selects rows for an allowed bulk action. |
| Status | Curation markers such as false positive or irrelevant. Hover a marker to read its meaning. |
| Gene 1 and Gene 2 | The two fusion partners selected from the normalized fusion call. |
| Effect | The predicted fusion effect, such as in-frame, when supplied by the source data. |
| Spanning pairs | Read-pair evidence supporting the fusion. |
| Unique spanning reads | Unique split-read or spanning-read evidence, depending on the caller payload. |
| Fusion points | The available breakpoint coordinates for both partners. |
| Tier | The current clinical tier. A dash means that the fusion has not been tiered. |
| Description | Caller or annotation description associated with the selected fusion call. |
| Callers | The tools that reported the fusion. |
| Actions | Permitted curation actions and a link to the fusion detail page. |

!!! info
    Evidence counts are displayed as supplied by the pipeline. Their clinical
    interpretation depends on the assay, caller, and validated laboratory
    thresholds.

## Search, Sort, and Export

- Enter a term in the table search field to search the server-side fusion data.
- Select one or more sortable headers to build a multi-column sort.
- Change the page size to control how many rows are displayed.
- Use **Export to CSV** to export the filtered fusion context generated by the
  API.

The table state is retained in the URL. Opening a fusion and returning to the
sample therefore preserves the active tab, search, page, and sort order.

## Curation Actions

Users with the required permission can mark or unmark selected fusions as
false positive or irrelevant. Coyote3 asks for confirmation before a mutation
is applied. Curated rows remain visible but use the standard subdued finding
style so that excluded findings are distinguishable from active findings.

## Reporting

The **Reports** tab is available only when reporting is enabled for the sample.
Report generation uses the filtered clinical context and the RNA report
sections permitted by the active ASPC. Review the rendered preview before
saving a report artifact.

For the configuration rules that determine visible analyses and report
sections, see
[Configuration identity and audit](../architecture/configuration_identity_and_audit.md)
and
[Reporting workflow](../product/reporting_workflow_and_variant_snapshots.md).
